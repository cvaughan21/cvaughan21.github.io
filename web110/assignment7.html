First, I started with the three TutorialsPoint lessons. I’m somewhat familiar with the OSI model, as I have had to learn about it through my work. The TCP/IP model is similar, but condenses the Phsyical and Data Link layers into one layer, Host-to-network. This layer connects the host to the network through protocol, allowing for IP packets to be sent over it. The most interesting thing to me was that Internet Protocol is unreliable independently, and must be paired with a model like TCP to be dependable. Similarly, UDP is also unreliable, and is therefore only used by the application to transmit small amounts of data at a time. Next I moved on to the Windows based IP activities. I’ve had plenty of experience troubleshooting both my own network issues as well as helping others, so I was familiar with a lot of the settings. I use a wired connection at work, but have had to restart my home router, as well as set up manual connections using IP addresses when it’s uncooperative. I then went to the Ipconfig activities. After opening the command prompt and typing “ipconfig” I was able to see all my current network configuration statuses. All of them were disconnected with the exception of Wireless LAN Adapter WIFI, which makes sense as I am currently using a wireless connection. The next activity had me use “ipconfig /all” which gave me a more detailed analysis of each adaptor. After releasing and renewing DHCP-Assigned addresses, the IP address is now the same as it was originally. I then went on to Ping/Host. After pinging the different IPv4, gateways, and internet hosts, I was able to learn a variety of ways to ensure network connectivity is active on my machine. I was able to see that pinging an internet host by IPv6 name took an average of 9ms per trip.
